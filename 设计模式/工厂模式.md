## 工厂模式

在 C++ 中，要实现工厂模式并确保派生类不能被直接实例化，只能通过工厂类的静态方法创建，可以通过以下方式实现：

1. **将派生类的构造函数设为私有或保护**：这样外部代码无法直接调用构造函数实例化对象。
2. **工厂类作为友元**：将工厂类声明为派生类的友元（`friend`），使其能够访问派生类的私有/保护构造函数。
3. **提供静态工厂方法**：在工厂类中定义静态方法，用于创建并返回派生类的实例（通常通过指针或智能指针返回）。

以下是一个完整的代码示例，展示如何实现这种设计：

```cpp
#include <iostream>
#include <memory>

// 前向声明基类
class Base;

// 工厂类
class Factory {
public:
    // 静态方法创建派生类 Derived1
    static std::unique_ptr<Base> createDerived1() {
        return std::make_unique<Derived1>();
    }

    // 静态方法创建派生类 Derived2
    static std::unique_ptr<Base> createDerived2() {
        return std::make_unique<Derived2>();
    }

private:
    // 工厂类无需实例化，构造函数设为私有
    Factory() = delete;
};

// 抽象基类
class Base {
public:
    virtual ~Base() = default;  // 虚析构函数，确保派生类正确析构
    virtual void print() const = 0;  // 纯虚函数，使 Base 为抽象类
};

// 派生类 Derived1
class Derived1 : public Base {
public:
    void print() const override {
        std::cout << "I am Derived1" << std::endl;
    }

private:
    // 构造函数设为私有
    Derived1() = default;

    // 将工厂类声明为友元，允许其访问构造函数
    friend class Factory;
};

// 派生类 Derived2
class Derived2 : public Base {
public:
    void print() const override {
        std::cout << "I am Derived2" << std::endl;
    }

private:
    // 构造函数设为私有
    Derived2() = default;

    // 将工厂类声明为友元
    friend class Factory;
};

// 测试代码
int main() {
    // 无法直接实例化派生类
    // Derived1 d1;  // 错误：构造函数是私有的
    // Derived2 d2;  // 错误：构造函数是私有的

    // 通过工厂类创建对象
    auto obj1 = Factory::createDerived1();
    auto obj2 = Factory::createDerived2();

    // 调用方法
    obj1->print();  // 输出: I am Derived1
    obj2->print();  // 输出: I am Derived2

    return 0;
}
```

### 实现要点：
1. **基类 `Base`**：
   - 定义为抽象类（通过纯虚函数 `print`），不能直接实例化。
   - 提供虚析构函数，确保通过基类指针删除派生类对象时正确释放资源。

2. **派生类 `Derived1` 和 `Derived2`**：
   - 构造函数设为 `private`，防止外部直接实例化。
   - 使用 `friend class Factory` 声明工厂类为友元，使其可以调用私有构造函数。

3. **工厂类 `Factory`**：
   - 提供静态方法 `createDerived1` 和 `createDerived2`，返回 `std::unique_ptr<Base>` 类型，确保对象的所有权管理。
   - 构造函数设为私有，防止实例化工厂类本身（纯静态类）。
   - 使用 `std::make_unique` 创建对象，避免手动 `new`，提高安全性和简洁性。

4. **智能指针**：
   - 使用 `std::unique_ptr` 返回对象，确保内存管理的现代化和安全性。如果需要共享所有权，可以改为 `std::shared_ptr`。

### 输出结果：
运行上述代码，将输出：
```
I am Derived1
I am Derived2
```

### 优点：
- **强制工厂创建**：派生类的私有构造函数确保只能通过工厂类创建实例。
- **类型安全**：通过基类指针（或智能指针）访问派生类，支持多态。
- **资源管理**：使用智能指针避免内存泄漏。

### 扩展：
如果需要支持更多派生类，只需：
1. 在每个新派生类中将构造函数设为私有，并添加 `friend class Factory`。
2. 在 `Factory` 类中添加对应的静态创建方法。

例如，添加一个 `Derived3`：
```cpp
class Derived3 : public Base {
public:
    void print() const override {
        std::cout << "I am Derived3" << std::endl;
    }
private:
    Derived3() = default;
    friend class Factory;
};

// 在 Factory 类中添加：
static std::unique_ptr<Base> createDerived3() {
    return std::make_unique<Derived3>();
}
```



以上设计是 C++ 中工厂模式的一种常见实现方式，尤其是在需要控制对象创建并隐藏派生类细节的场景下。不过，C++ 中的工厂模式有多种变体，具体实现会根据需求有所不同。让我们分析一下这种设计的常见性以及它的适用场景，同时对比其他工厂模式的实现方式。

### 当前设计的特点与常见性
你提供的示例（通过私有构造函数 + 友元 + 静态工厂方法）在 C++ 中确实是一种常见的工厂模式实现，尤其在以下情况下：
1. **限制直接实例化**：通过将派生类的构造函数设为私有或保护，并结合友元机制，确保只能通过工厂创建对象。这是 C++ 中实现“创建控制”的典型手段。
2. **静态工厂方法**：使用静态方法来创建对象是工厂模式的核心特性之一，广泛用于 C++，因为它简单、直观，且无需实例化工厂类本身。
3. **智能指针返回**：返回 `std::unique_ptr` 或 `std::shared_ptr` 是现代 C++ 中的惯例，符合 RAII 原则，避免了裸指针带来的内存管理问题。

这种设计在一些经典 C++ 书籍（如《设计模式：可复用面向对象软件的基础》）和开源项目中可以看到，尤其是在需要严格封装和多态支持的场景中。

### C++ 中工厂模式的常见变体
工厂模式在 C++ 中有几种常见的实现方式，具体取决于需求：

#### 1. 简单工厂（如你的示例）
- **特点**：一个工厂类通过静态方法创建所有派生类对象。
- **适用场景**：派生类种类固定且数量较少，创建逻辑简单。
- **代码示例**：你提供的代码就是这种模式。
- **优缺点**：
  - 优点：实现简单，易于理解和维护。
  - 缺点：违反开放-封闭原则（OCP），新增派生类需要修改工厂类。

#### 2. 工厂方法模式
- **特点**：定义一个抽象工厂类，每个具体工厂类负责创建一种具体产品（派生类）。
- **适用场景**：需要动态扩展派生类，且不希望修改已有代码。
- **代码示例**：
```cpp
#include <memory>

class Base {
public:
    virtual ~Base() = default;
    virtual void print() const = 0;
};

class Derived1 : public Base {
public:
    void print() const override { std::cout << "Derived1\n"; }
protected:
    Derived1() = default;  // 保护构造函数
};

class Factory {
public:
    virtual ~Factory() = default;
    virtual std::unique_ptr<Base> create() const = 0;
};

class Derived1Factory : public Factory {
public:
    std::unique_ptr<Base> create() const override {
        return std::make_unique<Derived1>();
    }
};
```
- **优缺点**：
  - 优点：符合 OCP，新增派生类只需添加新工厂类。
  - 缺点：代码量增加，复杂度稍高。

#### 3. 抽象工厂模式
- **特点**：一个工厂接口创建一组相关对象（产品族）。
- **适用场景**：需要创建多个相关对象，且这些对象之间有依赖关系。
- **代码示例**（简化版）：
```cpp
class Button { public: virtual void render() = 0; virtual ~Button() = default; };
class Window { public: virtual void show() = 0; virtual ~Window() = default; };

class WinButton : public Button { public: void render() override { std::cout << "Win Button\n"; } };
class WinWindow : public Window { public: void show() override { std::cout << "Win Window\n"; } };

class GUIFactory {
public:
    virtual std::unique_ptr<Button> createButton() = 0;
    virtual std::unique_ptr<Window> createWindow() = 0;
    virtual ~GUIFactory() = default;
};

class WinFactory : public GUIFactory {
public:
    std::unique_ptr<Button> createButton() override { return std::make_unique<WinButton>(); }
    std::unique_ptr<Window> createWindow() override { return std::make_unique<WinWindow>(); }
};
```
- **优缺点**：
  - 优点：支持产品族的创建，扩展性强。
  - 缺点：接口复杂，适合大型系统。

#### 4. 注册式工厂（反射式）
- **特点**：通过类型注册机制（如字符串映射到创建函数），动态创建对象。
- **适用场景**：派生类数量多且可能动态加载（如插件系统）。
- **代码示例**：
```cpp
#include <functional>
#include <unordered_map>

class Base {
public:
    virtual ~Base() = default;
    virtual void print() const = 0;
};

class Derived1 : public Base {
public:
    void print() const override { std::cout << "Derived1\n"; }
private:
    Derived1() = default;
    friend class Factory;
};

class Factory {
public:
    using Creator = std::function<std::unique_ptr<Base>()>;
    static void registerType(const std::string& type, Creator creator) {
        creators[type] = creator;
    }
    static std::unique_ptr<Base> create(const std::string& type) {
        auto it = creators.find(type);
        return (it != creators.end()) ? it->second() : nullptr;
    }
private:
    static std::unordered_map<std::string, Creator> creators;
};
std::unordered_map<std::string, Factory::Creator> Factory::creators;

// 注册类型
struct Registrar {
    Registrar() {
        Factory::registerType("Derived1", []() { return std::make_unique<Derived1>(); });
    }
} static registrar;
```
- **优缺点**：
  - 优点：高度灵活，支持动态扩展。
  - 缺点：依赖运行时注册，性能稍低。
