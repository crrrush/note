## 是什么

程序编译链接的时候需要的程序所使用的外部代码的实现

这些库是被编译好的代码，按照需求分成不同格式的文件，其内容的格式也会因此不同



## 为什么

上网的故事，家里，网吧



交付库 -> 库文件(.a、 .so) + 匹配的头文件都给别人

安装的本质就是拷贝







## 怎么做

`ldd`，输入可执行文件，查看依赖库

`file`，输入可执行文件，查看链接等信息



使用gcc生成编译各阶段的文件

* 预处理`gcc -E test.cc -o test.i`
* 编译`gcc -S test.cc -o test.s`
* 汇编`gcc -c test.cc -o test.o`



### 生成静态库

```
[root@localhost linux]# ar -rc libmymath.a add.o sub.o
ar是gnu归档工具，rc表示(replace and create)

查看静态库中的目录列表
[root@localhost linux]# ar -tv libmymath.a
rw-r--r-- 0/0 1240 Sep 15 16:53 2017 add.o
rw-r--r-- 0/0 1240 Sep 15 16:53 2017 sub.o
t:列出静态库中的文件
v:verbose 详细信息
```

静态库链接方式（指令）

`libmymath.a`的名字取掉`lib`和`.a`，即`mymath`



编译时链接静态库

`gcc -o mymath main.c -I./mylib/inlcude -L./mylib/lib -lmymath `



* gcc默认是动态链接的（建议行为），对于特定的一个库，究竟是动，还是静，取决于你提供的是动态库还是静态库
* 静态链接的会直接将库代码复制到程序中



#### 库搜索路径

* `-L`指定的目录，从左至右搜索
* 环境变量指定的（`LIBRARY_PATH`）
* 由系统指定的目录，也就是安装路径：`/usr/include/` 或 `/lib64/`



gcc编译链接动静态库选项相同（`-I -L -l`）





### 生成动态库

#### 相关选项

* -fPIC：产生与位置无关码
* shared：表示生成共享库格式
* 库名规则：libxxx.so



```
gcc -fPIC sub.c add.c
gcc -shared -o libmymath.so *.o
```



#### 使用

```
gcc main.c -L./lib -lmymath
```





#### 运行动态库

动态库需要系统加载起来！！！除非可执行文件和动态库在同一个路径，系统能找到，但是正常不能这样放

* 环境变量LD_LIBRARY_PATH`echo $LD_LIBRARY_PATH`

  export添加路径到这个环境变量下，这个方式在本次登录有效，永久生效得改变环境变量相关的配置文件（麻烦）

* 或者拷贝到系统共享库里（一般指`/usr/lib`），系统会加载(永久有效)

* 配置文件`/etc/ld.so.conf.d/`，这个路径下的conf配置文件，将动态库路径放入任意一个conf文件中（手动刷新`ldconfig`）（永久有效）
* 当前目录（可执行目标文件的路径）创建动态库的软链接或者硬链接（名字需一样）（永久有效）



静态库是不需要加载的，编译可执行程序里编进去了，函数编址在代码区，跟自己的代码一样，是确定的绝对编址

**编译动态库需要添加位置无关码！**

**动态库的加载**

动态库中指定函数的地址，写入可执行程序中，这个地址是偏移量，是相对编址(start（任意，可改）:**偏移地址**)，程序运行中，遇到标识好的动态库的函数/数据，就去加载动态库，并将该动态库映射到共享区
