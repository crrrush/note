背景：一个系统需要管理计算机的软硬件资源来对外提供服务，从最底层的硬件（处理器、主存和I/O设备等），到I/O设备驱动，到文件，到虚拟内存和指令集架构，再到进程，一层层向下管理（先描述再组织）和向上提供服务





## 是什么/为什么



而一个进程的概念绝不仅仅是“运行起来的程序”这么简单。而是一个承担了系统分配给这个程序的资源以及管理这些资源的实体。

同时，现代系统上通常不是只有一个进程，系统也需要对这些进程管理起来（先描述再组织）。所以根据进程的各种属性设计字段，以及根据对进程管理（调度方式，或者说增删查改）的需求，增加管理所需字段，最后通过这个数据结构模型进行管理

这个描述进程的数据结构也叫做PCB（process contr block），在Linux中，PCB的具体实现叫做`task_struct`，这是Linux内核中的一种数据结构

**其实这里可以清楚的知道，进程PCB是操作系统用于管理进程资源而设计处理来的数据结构，所以学习进程PCB也就是在学习这个数据结构体的字段设计以及结构设计**

**还有需要注意的是，一个完整的进程应当是指进程PCB+页表以及其映射在主存上的资源以及在外存（磁盘、固态、网络等）中打开的文件**

### 进程状态

#### 总体概述

是什么？具体实现是什么？每个状态的含义

```c
/*
 * The task state array is a strange "bitmap" of
 * reasons to sleep. Thus "running" is zero, and
 * you can test for combinations of others with
 * simple bit tests.
*/
static const char * const task_state_array[] = {
"R (running)", /* 0 */
"S (sleeping)", /* 1 */
"D (disk sleep)", /* 2 */
"T (stopped)", /* 4 */
"t (tracing stop)", /* 8 */
"X (dead)", /* 16 */
"Z (zombie)", /* 32 */
};

```



* R运行状态（running） : 并不意味着进程一定在运行中，它表明进程要么是在运行中要么在运行队列里

* S睡眠状态（sleeping): 意味着进程在等待事件完成（这里的睡眠有时候也叫做可中断睡眠）

* D磁盘休眠状态（Disk sleep）：有时候也叫不可中断睡眠状态（uninterruptible sleep），在这个状态的进程通常会等待IO的结束

  为了**避免进程向磁盘写入关键数据时被操作系统杀掉**，所以**磁盘休眠（深度睡眠）状态不可被杀掉！**

* T停止状态（stopped）： 可以通过发送 SIGSTOP 信号给进程来停止（T）进程。这个被暂停的进程可以通过发送 SIGCONT 信号让进程继续运行

* X死亡状态（dead）：这个状态只是一个返回状态，你不会在任务列表里看到这个状态  



进程状态查看的指令：

* `ps aux`
* `ps axj`



#### 深究

##### 浅度睡眠状态

* **广义上的”阻塞状态“**。意味着进程在等待事件完成。
* 此状态的进程可以被终止
* 会对外部信号做出响应
* 使用指令查看进程状态时，发现睡眠状态的进程符号有`S`和`S+`，其中前台进程带`＋`，后台进程不带并且后台进程不能使用`ctrl + c`（即发送`SIGINT`信号）关闭。

* `kill -19 [PID]`或者`kill -SIGSTOP [PID]` 向pid进程发送19号命令（也就是`SIGSTOP`），停止进程运行
* `kill -18 [PID]`或者`kill -SIGCONT [PID] `向pid进程发送18号命令（也就是`SIGCONT`），使停止运行的进程继续运行

##### 追踪停止状态

* 查询显示的状态为t，与停止状态T不同
* **debug程序时（不断向系统发送SIGSTOP，SIGCONT信号过程中）**
* **程序停在断点处时，就是t状态**
* 现在一般而言，T，t不分家，都是停止状态



##### 死亡状态

进程结束时会释放进程所属所有资源，不过一般这个过程极快速。



##### 僵尸状态（Linux特有状态）

处于僵尸状态的进程，也叫做僵尸进程

精灵进程或者守护进程



* 进程结束不会立即释放，会等一小会（当然这时发送`SIGKILL`信号是无法杀死的，毕竟从结构逻辑上讲，你无法杀死一个已经死掉的进程，本质是这个进程已经被杀死但是还没有被回收处理妥当）
* **当一个进程在退出的时候，退出信息会由OS写入到当前退出进程的PCB中，可以允许进程的代码和数据空间被释放，但是不能允许进程的PCB被立刻释放！**
* OS必须维护这个退出的进程的PCB结构
* 原因：在进程死亡时，操作系统或者父进程需要值得进程退出的原因（退出码），因此它的PCB里的退出信息不会被释放
* 父进程或者OS读取后，PCB状态先被改成X死亡状态，才会被释放



###### 僵尸进程的危害

* 进程的退出状态必须被维持下去，直到父进程读取返回码。但是如**果父进程一直不读取，子进程就会一直处于Z状态**
* 进程一直处于退出状态，PCB结构体（其他资源已经被回收，退出码作为进程的基本属性，存储在PCB中）一直无法被回收。也就是进程的资源一直无法被完全回收。也就是**内存泄漏**



###### 孤儿进程

* 父进程先于子进程退出，此时子进程就叫做**孤儿进程**。（当然，父进程退出并不会进入Z状态，除非父进程的父进程不处理）
* 父进程退出来了，子进程退出时由谁负责接收处理？——子进程的父进程先退出时，子进程要被领养，即子进程**被1号进程（systemd）领养**

### 进程优先级

#### 概述

是什么/为什么

* CPU资源分配的先后顺序，就是指**进程的优先权**（priority）
* 优先权高的进程有优先执行权利。配置进程优先权对多任务环境的Linux很有用，可以改善系统性能
* 可以将进程运行到指定CPU上，把不重要的进程安排到某个CPU，可以大大改善系统整体性能



##### 使用`ps -l`查看进程优先级

* UID : 代表执行者的身份
* PID : 代表这个进程的代号
* PPID ：代表这个进程是由哪个进程发展衍生而来的，亦即父进程的代号
* PRI ：代表这个进程可被执行的优先级，其值越小越早被执行
* NI ：代表这个进程的nice值  



##### PRI/NI

* PRI也还是比较好理解的，即进程的优先级，或者通俗点说就是程序被CPU执行的先后顺序，此值越小
  进程的优先级别越高
* 那NI呢?就是我们所要说的nice值了，其表示进程可被执行的优先级的修正数值
* PRI值越小越快被执行，那么加入nice值后，将会使得PRI变为： PRI(new)=PRI(old)+nice
* 这样，当nice值为负值的时候，那么该程序将会优先级值将变小，即其优先级会变高，则其越快被执行
* 所以，调整进程优先级，在Linux下，就是调整进程nice值
* nice其取值范围是-20至19，一共40个级别  



##### PRI vs NI

* 需要强调一点的是，进程的nice值不是进程的优先级，他们不是一个概念，但是进程nice值会影响到进程的优先级变化。
* 可以理解nice值是进程优先级的修正数据  



##### 使用top命令更改已存在进程的nice

1. top
2. 进入top后按`r`
3. 输入进程`PID`
4. 输入`nice`值



##### 其他概念/为什么会有优先级，为什么需要竞争

* 竞争性：系统进程数目众多，而CPU资源只有少量，甚至1个，所以**客观上进程之间是具有竞争属性的**，并且**不同进程的任务也存在优先级区别**，所以**需要使用优先级竞争资源**
* 独立性：多进程运行，需要独享各种资源，多进程运行期间互不干扰
* 并行: 多个进程在多个CPU下分别，同时进行运行，这称之为并行
* 并发: 多个进程在一个CPU下采用进程切换的方式，在一段时间之内，让多个进程都得以推进，称之为并发

环境变量的组织方式

每个进程都会收到一张环境变量表，环境变量表是一个字符指针数组，每个指针指向一个以`'\0'`为结尾的环境字符串



#### 通过代码获取环境变量

* 命令行第三个参数

  ```c
  #include <stdio.h>
  
  int main(int argc, char *argv[], char *env[])
  {                                              
      for(int i = 0;env[i];++i)
      {
        printf("%s\n", env[i]);
      }
  
      return 0;
  }
  ```

* 通过第三方变量`environ`获取

  ```c
  #include <stdio.h>
  
  int main()
  {
      extern char **environ;
      // libc中定义的全局变量environ指向环境变量表,environ没有包含在任何头文件中,所以在使用时 要用extern声明。 
      for(int i = 0;environ[i];++i)
      {                            
        printf("%s\n", environ[i]);
      }                  
                         
      return 0;          
  }                      
  ```



#### 通过系统调用获取或设置（指定）环境变量

* getenv

  ```c
  #include <stdio.h>                  
  #include <stdlib.h>
  
  int main()
  {
      printf("%s\n", getenv("PATH"));
      return 0;
  }
  ```

* putenv

  ```c
  // The  putenv()  function  adds  or  changes  the  value  of  environment variables.

  ```

  

#### 环境变量通常具有全局属性

可以被子进程继承下去

```c
#include <stdio.h>
#include <stdlib.h>

int main()
{
    char * env = getenv("MYENV");
    if(env) printf("%s\n", env);
    return 0;                        
}
```

1. 先运行此程序，没有打印出任何东西
2. 导出环境变量`export MYENV="hello world"  `
3. 再运行程序，发现打印出来了
4. 另外打开一个shell对话，运行此程序，没有打印出任何东西



**为什么？**

[Linux环境变量](https://creaink.github.io/post/Computer/Linux/Linux-env.html)

简单讲，环境变量查找表存储在main函数栈帧之前，使用fork创建子进程会直接复制，而子进程里修改环境变量当然不会影响到父进程。而使用exec系列函数进行程序替换时，有的接口会提供传递环境变量的选项，没有提供的会自行传递现有进程的环境变量

环境变量查找表指向的值（环境变量）根据是其否进行二次修改，存储在 main 栈之上或者堆中
