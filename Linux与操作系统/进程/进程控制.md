  多进程控制

## 进程创建

### fork函数

```c
#include <unistd.h>
pid_t fork(void);
// 返回值：自进程中返回0，父进程返回子进程id，出错返回-1
```



内核主要做以下工作：

* 分配新的内存块和内核数据结构给子进程
* 将父进程的部分数据结构内容拷贝至子进程
* 添加子进程到系统进程列表中
* fork返回，调度器开始调度



### 写时拷贝

创建子进程的时候，进程大部分资源是共享父进程的，对于只读的资源，一般一直共享，对于可写的数据，一般采用**写时拷贝**的策略，即任意一方写入时，拷贝一份该资源给另一个进程



### 常规用法

* 一个父进程希望子进程复制自己，并使父子进程同时执行不同代码段。例如，父进程等待客户端请求，子进程负责响应处理请求
* 一个进程要执行一个不同的程序。例如子进程从fork返回后，调用`exec`系列函数



### 调用失败的原因

* 系统中有太多的进程
* 用户创建的进程数超过了限制



## 进程终止

### 进程退出场景

* 代码运行完毕，结果正确
* 代码运行完毕，结果不正确
* 代码异常终止



### 进程常见退出方法

正常终止（可以通过`echo $？`查看进程退出码）

* 从`main`函数返回
* 调用`exit`
* 调用`_exit`



异常退出

* 例如，`ctrl + c`，信号终止
* 系统级异常，大约是指进程在尝试访问或者修改一块进程无权限访问或修改的数据，具体来讲，就是MMU通过地址寻址时，发现该块数据权限要求高于进程权级
* 还有一类异常是计算异常，例如除零操作，CPU不能执行此行为，触发异常进入内核态，并通知进程





#### `_exit`函数

```c
#include <unistd.h>
void _exit(int status);
// 参数：status 定义了进程的终止状态，父进程通过wait来获取该值
// The function _exit() terminates the calling process "immediately".  
// Any open file descriptors belonging to the process are closed; 
// any children of the process are inherited by process 1, init, 
// and the process's parent is sent  a  SIGCHLD signal.

// The value status is returned to the parent process as the process's exit status, 
// and can be collected using one of the wait(2) family of calls.
```

* 说明：虽然`status`是`int`，但是仅有低8位可以被父进程所用。所以`_exit(-1)`时，在终端执行`echo $?`发现返回值是255



#### `exit`函数

```c
#include <stdlib.h>
void exit(int status);
```

C语言封装的系统调用，最后也会调用`_exit`，但在调用之前，还会做其他工作：

1. 执行用户通过`atexit`或`on_exit`注册的清理函数
2. 关闭所有打开的流，并刷新所有的缓存数据
3. 调用`_exit`



#### `return`退出

最常见的退出方式。执行`return n`等同于执行`exit(n)`，因为调用`main`的运行时函数会将`main`的返回值当作`exit`的参数



## 进程等待

### 进程等待必要性/为什么

* 在进程中讲过，进程状态中有僵尸状态，父进程不等待子进程，在子进程退出时及时接收退出信息就会导致子进程资源一直回收不完全，进而造成内存泄漏
* 并且一旦进程编程进入僵尸状态，就无法杀掉，只能等父进程处理，或者杀掉父进程
* 最后，父进程交给子进程执行的任务，需要关心完成的情况（结果如何，是否是异常退出等）



### 方法/怎么做

#### `wait`接口

```c
#include <sys/types.h>
#include <sys/wait.h>

pid_t wait(int *status);
// 成功则返回被等待进程pid，失败返回-1
// 参数status，输出型参数，获取子进程退出状态，不关心则可以设为NULL
```



#### `waitpid`接口

```c
#include <sys/types.h>
#include <sys/wait.h>

pid_t waitpid(pid_t pid, int *status, int options);
// 返回值：
// 当正常返回的时候waitid返回收集到的子进程的进程ID
// 如果设置了选项WNOHANG，而调用中waitpid发现没有已退出的子进程可收集，则返回0
// 如果调用中出错，则返回-1，这时errno会被设置成相应的值以指示错误类型

// 参数：
// pid：
//   Pid=-1,等待任一个子进程。与wait等效。
//   Pid>0.等待其进程ID与pid相等的子进程。
// status:
//   WIFEXITED(status): 若为正常终止子进程返回的状态，则为真。（查看进程是否是正常退出）
//   WEXITSTATUS(status): 若WIFEXITED非零，提取子进程退出码。（查看进程的退出码）
// options:
//   WNOHANG: 若pid指定的子进程没有结束，则waitpid()函数返回0，不予以等待。若正常结束，则返回该子进程的ID
```

* 如果子进程已经退出，调用`wait`/`waitpid`时，`wait`/`waitpid`会立即返回，并且释放资源，获得子进程退出信息
* 如果在任意时刻调用`wait`/`waitpid`，子进程存在且正常运行，则进程可能堵塞
* 如果不存在该子进程，则立即出错返回



#### 获取子进程`status`

* `wait`/`waitpid`的`status`参数，该参数是一个输出型参数，由操作系统填充
* 如果传递NULL则视为不关心子进程的退出状态
* 不能简单当作整型，需要当作位图解析信息（总体只研究低16比特位）
  * 正常终止：高8位为退出状态，低8位为0
  * 被信号杀死：高8为不使用，低8位中，高1位为**core dump**标志，低7位为终止信号



#### 具体实现

* 阻塞等待
* 非阻塞等待，循环非阻塞式调用等待接口
* 通过`signal`注册`SIGCHILD`信号回调函数





## 进程程序替换

### 是什么/为什么

创建进程并运行其他程序



### 替换原理

用`fork`创建子进程后执行的是和父进程相同的程序(但有可能执行不同的代码分支)，子进程往往要调用一种exec函数以执行另一个程序。当进程调用一种exec函数时，该进程的**用户空间代码和数据**完全被新程序替换，从新程序的启动例程开始执行。调用exec并不创建新进程，所以调用exec前后该进程的id并未改变



### 替换函数

`exec`系列函数

```c
#include <unistd.h>
int execl(const char *path, const char *arg, ...);
int execlp(const char *file, const char *arg, ...);
int execle(const char *path, const char *arg, ..., char * const envp[]);
int execv(const char *path, char *const argv[]);
int execvp(const char *file, char *const argv[]);
int execvpe(const char *file, char *const argv[], char *const envp[]);
```



```c
#include <unistd.h>
int execve(const char *filename, char *const argv[], char *const envp[]);
```



### 函数解释

* 这些函数如果调用成功则加载新的程序从启动代码开始执行，不再返回
* 如果调用出错则返回-1
* 所以exec函数只有出错的返回值而没有成功的返回值



命名理解

* l（list）：表示参数采用列表
* v（vector）：参数用数组
* p（path）：有p自动搜索环境变量PATH，从PATH记录的路径中找可执行文件
* e（env）：表示自己维护环境变量



```c
#include <unistd.h>
// 用法举例
int main()
{
    char *const argv[] = {"ps", "-ef", NULL};
    char *const envp[] = {"PATH=/bin:/usr/bin", "TERM=console", NULL};
    execl("/bin/ps", "ps", "-ef", NULL);
    // 带p的，可以使用环境变量PATH，无需写全路径
    execlp("ps", "ps", "-ef", NULL);
    // 带e的，需要自己组装环境变量
    execle("ps", "ps", "-ef", NULL, envp);
    execv("/bin/ps", argv);
    // 带p的，可以使用环境变量PATH，无需写全路径
    execvp("ps", argv);
    // 带e的，需要自己组装环境变量
    execve("/bin/ps", argv, envp);
    exit(0);
}
```

事实上,只有`execve`是真正的系统调用,其它五个函数最终都调用 `execve`,所以`execve`在man手册 第2节,其它函数在man手册第3节
