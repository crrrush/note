#### 认识端口号

端口号（port）是传输层协议的内容

* 端口号是一个2字节16位的整数
* 端口号用来标识一个进程，告诉操作系统，当前的这个数据要交给哪一个进程来处理
* IP地址+端口号能够标识网络上的某一台主机的某一个进程
* 一个端口号只能被一个进程占用



#### 理解“端口号”和“进程ID”

另外，一个进程可以绑定多个端口号；但是一个端口号不能被多个进程绑定

#### 网络字节序

磁盘文件中的多字节数据相对于文件中的偏移地址也有大端小端之分，网络数据流同样有大端小端之分。

* 发送主机通常将发送缓冲区中的数据按内存地址从低到高的顺序发出
* 接收主机把从网络上接到的字节依次保存在接收缓冲区中,也是按内存地址从低到高的顺序保存
* 即**发送出去的数据顺序和接收到的是一样的**
* 网络数据流的地址应这样规定：先发出的数据是低地址，后发出的数据是高地址
* **TCP/IP协议规定，网络数据流应采用大端字节序，即低地址高字节**
* 不管这台主机是大端机还是小端机，都会按照这个TCP/IP规定的网络字节序来发送/接收数据
* 如果当前发送主机是小端，就需要先将数据转成大端，否则就忽略，直接发送即可
* 接收同理

```c
// 建立连接 (TCP, 客户端)

```



#### sockaddr结构

socket API是一层抽象的网络编程接口，适用于各种底层网络协议，如IPv4、 IPv6，以及后面要讲的UNIX Domain Socket。然而，各种网络协议的地址格式并不相同

* IPv4和IPv6的地址格式定义在`netinet/in.h`中，IPv4地址用`sockaddr_in`结构体表示，包括16位地址类型，16位端口号和32位IP地址
* IPv4、 IPv6地址类型分别定义为常数`AF_INET`、`AF_INET6`。这样，只要取得某种`sockaddr`结构体的首地址，不需要知道具体是哪种类型的`sockaddr`结构体，就可以根据地址类型字段确定结构体中的内容
* socket API可以都用`struct sockaddr *`类型表示，在使用的时候需要强制转化成`sockaddr_in`； 这样的好处是程序的通用性，可以接收IPv4，IPv6，以及UNIX Domain Socket各种类型的sockaddr结构体指针做为参数;

可以看出，这是一个多态设计的函数接口，对于这个结构体的使用类似于子类切片给父类



```c
typedef unsigned short int sa_family_t;

struct sockaddr {
    sa_family_t sa_family;
    char        sa_data[14];
}


/* Type to represent a port. */
typedef uint16_t in_port_t;

/* Internet address. */
typedef uint32_t in_addr_t;
struct in_addr
{
 in_addr_t s_addr;
};

/* /usr/include/netinet/in.h */
/* Structure describing an Internet socket address. */
struct sockaddr_in
{
 __SOCKADDR_COMMON (sin_);
 in_port_t sin_port;         /* Port number. */
 struct in_addr sin_addr;    /* Internet address. */

 /* Pad to size of `struct sockaddr'. */
 unsigned char sin_zero[sizeof (struct sockaddr) -
            __SOCKADDR_COMMON_SIZE -
            sizeof (in_port_t) -
            sizeof (struct in_addr)];
};
```

```c
in_addr_t inet_lnaof(struct in_addr in);
in_addr_t inet_netof(struct in_addr in);

```

使用示例

```c
int main(int argc, char *argv[])
{
    unsigned char buf[sizeof(struct in6_addr)];
    int domain, s;
    char str[INET6_ADDRSTRLEN];

    if (argc != 3) {
        fprintf(stderr, "Usage: %s {i4|i6|<num>} string\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    domain = (strcmp(argv[1], "i4") == 0) ? AF_INET :
             (strcmp(argv[1], "i6") == 0) ? AF_INET6 : atoi(argv[1]);

    s = inet_pton(domain, argv[2], buf);
    if (s <= 0) {
        if (s == 0)
            fprintf(stderr, "Not in presentation format");
        else
            perror("inet_pton");
        exit(EXIT_FAILURE);
    }

    if (inet_ntop(domain, buf, str, INET6_ADDRSTRLEN) == NULL) {
        perror("inet_ntop");
        exit(EXIT_FAILURE);
    }

    printf("%s\n", str);

    return 0;
}
```

##### 关于`inet_ntoa`

man手册上说，`inet_ntoa`函数，是把这个返回结果放到了静态存储区。这个时候不需要我们手动进行释放。但是多次调用这个函数呢？因为`inet_ntoa`把结果放到自己内部的一个静态存储区，这样第二次调用时的结果会覆盖掉上一次的结果

* 思考：如果有多个线程调用 `inet_ntoa`，是否会出现异常情况呢？
* 在APUE中，明确提出`inet_ntoa`不是线程安全的函数
* 但是在centos7上测试，并没有出现问题，可能内部的实现加了互斥锁
* 可写程序验证一下在自己的机器上`inet_ntoa`是否会出现多线程的问题
* 在多线程环境下，推荐使用`inet_ntop`，这个函数由调用者提供一个缓冲区保存结果，可以规避线程安全问题

## TCP

#### TCP socket API

```c
#include <sys/types.h>          /* See NOTES */
#include <sys/socket.h>

int socket(int domain, int type, int protocol);
```

* `socket()`打开一个网络通讯端口，如果成功的话，就像`open()`一样返回一个文件描述符
* 应用程序可以像读写文件一样用`read`/`write`在网络上收发数据
* 如果`socket()`调用出错则返回-1
* 对于IPv4，family参数指定为`AF_INET`
* 对于TCP协议，type参数指定为`SOCK_STREAM`，表示面向流的传输协议
* protocol参数的介绍暂略，指定为0即可



```c
// 绑定端口号 (TCP/UDP, 服务器)
int bind(int socket, const struct sockaddr *address, socklen_t address_len);
```

* 服务器程序所监听的网络地址和端口号通常是固定不变的，客户端程序得知服务器程序的地址和端口号后就可以向服务器发起连接。服务器需要调用`bind`绑定一个固定的网络地址和端口号
* `bind()`成功返回0，失败返回-1
* `bind()`的作用是将参数`sockfd`和`myaddr`绑定在一起，使`sockfd`这个用于网络通讯的文件描述符监听`myaddr`所描述的地址和端口号
* 前面讲过，`struct sockaddr *`是一个通用指针类型，`myaddr`参数实际上可以接受多种协议的`sockaddr`结构体，而它们的长度各不相同，所以需要第三个参数`addrlen`指定结构体的长度

对myaddr参数初始化

```c
sockaddr_in sa;
bzero(&sa, sizeof(sa));
sa.sin_family = AF_INET;
sa.sin_addr.s_addr = htonl(INADDR_ANY);
sa.sin_port = htons(_port);
```

* 将整个结构体清零
* 设置地址类型为`AF_INET`
* 网络地址为`INADDR_ANY`，这个宏表示本地的任意IP地址，因为服务器可能有多个网卡，每个网卡也可能绑定多个IP 地址，这样设置可以在所有的IP地址上监听，直到与某个客户端建立了连接时才确定下来到底用哪个IP 地址
* 端口号为`_port`



```c
// 开始监听socket (TCP, 服务器)
int listen(int socket, int backlog);
```

* `listen()`声明sockfd处于监听状态，并且最多允许有`backlog`个客户端处于连接等待状态，如果接收到更多的连接请求就忽略，这里设置不会太大（一般是5），具体意义TCP协议中可以看出
* `listen()`成功返回0，失败返回-1



```c
// 接收请求 (TCP, 服务器)
int accept(int socket, struct sockaddr* address, socklen_t* address_len);
```

* 三次握手完成后，服务器调用`accept()`接受连接
* 如果服务器调用`accept()`时还没有客户端的连接请求，就阻塞等待直到有客户端连接上来
* `address`是一个输出型参数，`accept()`返回时传出客户端的地址和端口号
* 如果给`addr`参数传NULL，表示不关心客户端的地址
* `addrlen`参数是一个输入输出型参数（value-result argument），传入的是调用者提供的，缓冲区`addr`的长度以避免缓冲区溢出问题，传出的是客户端地址结构体的实际长度（有可能没有占满调用者提供的缓冲区）
* 返回值返回一个文件描述符



```c
// 建立连接 (TCP, 客户端)
int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

* 客户端需要调用`connect()`连接服务器
* `connect`和`bind`的参数形式一致，区别在于`bind`的参数是自己的地址，而`connect`的参数是对方的地址
* `connect()`成功返回0，出错返回-1

### 通讯流程

基于TCP协议的客户端/服务器程序的简单流程：

1. **建立连接**

   * 服务端创建套接字，绑定IP和端口，设置监听状态，等待连接请求（调用`accept`）
   * 客户端创建套接字，向目标IP和端口发起TCP连接建立请求（调用`connect`）
   * 客户端发送请求建立连接的TCP数据报，其中报头中的SYN标志位置为1
   * 服务端接收到报头带有SYN标志位的报文，也就是请求建立连接的报文
   * 服务端向客户端发送带有SYN标志位和ACK标志位的报文，也就是确认建立连接的报文
   * 客户端接收到确认建立连接的报文，再发送一个应答报文，也就是一个报头ACK标志位为1的报文，然后`connect`调用结束返回，连接建立完成

   其中，这三段报文丢失的情况：

   * 第一段客户端发起建立连接的请求报文丢失，超时后触发超时重传
   * 第二段服务端确认建立连接的报文丢失时，客户端先触发超时重传机制，重发请求连接报文，如果这一段报文也丢失，就到了服务端触发超时重传，重新发送确认建立连接的报文，双方超时重传次数达到一定程度后就会连接失败
   * 第三段客户端发送确认建立连接报文的确认应答丢失，其实这个报文丢失已经不要紧了，此时通信双方已经认为连接建立完成了。而且，TCP报文是有序号的，当服务端接收到后续序号报文则可视为对前面已发生报文的确认（前序号的报文发送过才会继续发送后续序号的报文）

   基于TCP协议的设计，三次握手除了建立连接以外还担负着其他任务

   * 窗口探测，向对方发送的报文含有自己接收缓冲区的大小，也就是互相交换了接收缓冲区大小
   * 超时重传时间的探测，这个时间是动态的，一开始是500ms，指数级递增，三次握手后双方都能确认一个超时重传时间的基准值

2. **保持通信**

   * 连接建立完成后，TCP协议提供全双工的通信服务，即双方可以同时写数据（本质是有读写缓冲区）
   * 服务端从`accept()`返回，获得一个文件描述符，然后使用`read()`和`write()`进行读和写，就像文件一样，如果没有数据到达或者说读写条件不满足就阻塞等待
   * 客户端从`connect()`返回，获得一个文件描述符，操作相同
   * 双方写下的数据由TCP协议确保完整有序传送到对方（当然，也可能因各种问题做不到，这是会报错）
   * 双方`read()`和`write()`循环调用，向对方发送处理好数据，和接收处理对方发过来的数据

3. **关闭连接**

   * 客户端调用`close()`关闭连接，向服务器发送带有FIN标志位的报文
   * 服务端收到带有FIN标志位的报文，也就是请求断开连接的报文，则向客户端发送带有FIN和ACK标志位的报文，代表确认收到客户端断开连接请求的报文和确认断开连接（这里可视为四次挥手的第二次和第三次，这两次在实操上大概率也是连在一起的）
   * 客户端接收到确认断开连接的报文，再返回一个ACK给服务端
