### MySQL 数据类型概述

数据类型本身也是一种**约束**，倒逼程序员尽可能进行正确的插入，保证数据插入的合法性。输入的字符不符合类型要求会被直接拒绝，而有些数据比如float可能会有精度损失。

MySQL 数据类型用于定义数据库中列可以存储的数据种类，合理选择数据类型可以优化存储空间、提高查询性能并确保数据完整性。MySQL 的数据类型主要分为以下几类：

------

### **1. 数值类型**

#### **整数类型**



| 数据类型      | 存储空间 | 范围（有符号）                  | 范围（无符号）     |
| ------------- | -------- | ------------------------------- | ------------------ |
| TINYINT       | 1 字节   | -128 到 127                     | 0 到 255           |
| SMALLINT      | 2 字节   | -32,768 到 32,767               | 0 到 65,535        |
| MEDIUMINT     | 3 字节   | -8,388,608 到 8,388,607         | 0 到 16,777,215    |
| INT / INTEGER | 4 字节   | -2,147,483,648 到 2,147,483,647 | 0 到 4,294,967,295 |
| BIGINT        | 8 字节   | 极大范围                        | 极大范围（非负）   |



- 特点

  ：

  - 可选 `UNSIGNED` 修饰符，使值范围仅包含非负数。
  - 常用 `AUTO_INCREMENT` 自动生成唯一标识。

------

#### **浮点类型**



| 数据类型     | 存储空间 | 精度                           | 示例               |
| ------------ | -------- | ------------------------------ | ------------------ |
| FLOAT        | 4 字节   | 单精度（约 7 位有效数字）      | 3.14, 1.23E10      |
| DOUBLE       | 8 字节   | 双精度（约 15 位有效数字）     | 3.141592653589793  |
| DECIMAL(M,D) | 可变     | 精确存储（M 总位数，D 小数位） | 123.45（M=5, D=2） |



- 特点

  ：

  - `FLOAT` 和 `DOUBLE` 用于近似值存储，`DECIMAL` 用于高精度财务计算。

------

### **2. 日期和时间类型**



| 数据类型  | 存储空间 | 格式                | 示例                |
| --------- | -------- | ------------------- | ------------------- |
| DATE      | 3 字节   | YYYY-MM-DD          | 2023-10-01          |
| TIME      | 3 字节   | HH:MM:SS            | 14:30:00            |
| DATETIME  | 8 字节   | YYYY-MM-DD HH:MM:SS | 2023-10-01 14:30:00 |
| TIMESTAMP | 4 字节   | YYYY-MM-DD HH:MM:SS | 自动记录时间戳      |
| YEAR      | 1 字节   | YYYY                | 2023                |



- 特点

  ：

  - `TIMESTAMP` 会自动更新为当前时间（受时区影响）。
  - 常用 `NOW()` 函数获取当前时间。

------

### **3. 字符串类型**

#### **定长字符串**

- CHAR(n)

  ：固定长度，存储时不足部分用空格填充。

  - 示例：`CHAR(10)` 存储 `'abc'` 实际占用 10 字节。

#### **变长字符串**

- VARCHAR(n)

  ：可变长度，存储时按实际长度占用空间。

  - 示例：`VARCHAR(10)` 存储 `'abc'` 实际占用 4 字节（3 字节数据 + 1 字节长度）。

#### **大文本类型**



| 数据类型   | 最大存储空间 | 特点     |
| ---------- | ------------ | -------- |
| TINYTEXT   | 255 字节     | 小文本   |
| TEXT       | 64 KB        | 中等文本 |
| MEDIUMTEXT | 16 MB        | 大文本   |
| LONGTEXT   | 4 GB         | 超大文本 |



- 特点

  ：

  - `TEXT` 类型不能设置默认值。
  - 查询 `TEXT` 字段时性能较低，建议避免存储过大的数据。

------

### **4. 二进制类型**

#### **定长二进制**

- BINARY(n)

  ：固定长度二进制数据。

  - 示例：`BINARY(10)` 存储 `'abc'` 实际占用 10 字节。

#### **变长二进制**

- VARBINARY(n)

  ：可变长度二进制数据。

  - 示例：`VARBINARY(10)` 存储 `'abc'` 实际占用 4 字节。

#### **大二进制类型**



| 数据类型   | 最大存储空间 | 特点           |
| ---------- | ------------ | -------------- |
| TINYBLOB   | 255 字节     | 小二进制数据   |
| BLOB       | 64 KB        | 中等二进制数据 |
| MEDIUMBLOB | 16 MB        | 大二进制数据   |
| LONGBLOB   | 4 GB         | 超大二进制数据 |



- 特点

  ：

  - 用于存储图片、音频等二进制文件。
  - 查询性能较低，建议存储文件路径而非文件本身。

------

### **5. JSON 类型**

- 特点

  ：

  - 用于存储 JSON 格式数据。
  - 提供 JSON 函数（如 `JSON_EXTRACT`）进行查询和操作。
  - 示例：`{"name": "Alice", "age": 30}`

------

### **6. 空间数据类型**

- 特点

  ：

  - 用于存储地理空间数据（如点、线、多边形）。
  - 需要 MySQL 空间扩展支持。

------

### **7. 位类型**

- BIT(n)

  ：存储位字段。

  - 示例：`BIT(8)` 存储 8 位二进制数。

------

### **选择数据类型的建议**

1. 数值类型

   ：

   - 整数：根据范围选择合适类型，避免浪费空间。
   - 浮点数：使用 `DECIMAL` 进行精确计算。

2. 字符串类型

   ：

   - 定长 vs 变长：根据数据长度是否固定选择。
   - 文本类型：根据数据大小选择，避免使用 `TEXT` 存储小数据。

3. 日期和时间类型

   ：

   - 根据需求选择，`TIMESTAMP` 适合记录创建/更新时间。

4. 二进制类型

   ：

   - 存储文件路径而非文件本身，提高查询性能。

5. JSON 类型

   ：

   - 用于存储结构化数据，避免过度使用导致查询复杂。

------

### **总结**

合理选择数据类型可以优化数据库性能、减少存储空间并确保数据完整性。在设计表结构时，应根据实际需求选择最合适的数据类型，并考虑未来的扩展性。
