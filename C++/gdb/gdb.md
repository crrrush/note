`gdb`（GNU调试器）是GNU项目发布的一个强大的Unix下的程序调试工具。它可以让你看到程序的执行流程，查看和修改变量的值等。在`gdb`中，打断点是一种常用的调试技术，它允许程序在特定位置停止执行，以便你可以检查程序的状态。

下面是如何在`gdb`中设置断点的基本步骤：

1. **启动gdb**

使用`gdb`命令启动你的程序，并附带任何需要的命令行参数。例如：

```bash
bash复制代码

gdb ./my_program
```

1. **在特定函数或行上设置断点**

   - 在函数上设置断点：

   ```
   复制代码
   
   bash`break function_name`
   ```

   例如，如果你的程序有一个名为`main`的函数，你可以使用以下命令在`main`函数的开始处设置断点：

   ```
   复制代码
   
   bash`break main`
   ```

   - 在特定行上设置断点：

   ```
   复制代码
   
   bash`break filename:line_number`
   ```

   例如，要在`main.cpp`文件的第10行上设置断点，你可以使用：

   ```
   复制代码
   
   bash`break main.cpp:10`
   ```

2. **运行程序**

使用`run`命令开始运行你的程序。当程序执行到你设置的断点时，它会停止。

```bash
bash复制代码

run [arguments]
```

1. **检查程序状态**

当程序在断点处停止时，你可以使用各种`gdb`命令来检查程序的状态，如变量的值、堆栈跟踪等。

```
* 查看变量的值：`print variable_name`  
* 继续执行到下一个断点：`continue` 或简写为 `c`  
* 单步执行：`next` 或简写为 `n`（执行下一行，如果当前行调用了其他函数，则整个函数都会执行完）和 `step` 或简写为 `s`（执行下一行，如果当前行调用了其他函数，则进入该函数并在第一行停止）  
* 查看堆栈跟踪：`backtrace` 或简写为 `bt`
```

\5. **删除断点**

如果你想删除某个断点，可以使用`delete`命令：

```bash
bash复制代码

delete breakpoint_number
```

你可以使用`info breakpoints`命令查看所有的断点及其编号。
\6. **退出gdb**

使用`quit`命令退出`gdb`。

请注意，这只是`gdb`的基本功能。`gdb`还提供了许多其他高级功能和命令，你可以查阅其官方文档以获取更多信息。
